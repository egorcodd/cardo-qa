# Cardo

Cardo создан для практики тестировщиков и использует микросервисную архитектуру. Это открытый учебный банковский стенд: один сценарий можно проверить через интерфейс, API, логи и базу данных.

В проекте есть намеренные дефекты для тренировки: можно составлять чек-листы и тест-кейсы, исследовать проблемы и оформлять баг-репорты. Деньги, карты и внешние банковские операции учебные; настоящие платежи не выполняются.

## Возможности

- Регистрация, вход, профиль и настройки пользователя.
- Карты и счета в RUB, USD и EUR, пополнение, переводы и обмен валют.
- Заморозка карт, получатели, лимиты и история операций.
- Cardo Плюс, баллы и награды.
- Уведомления, напоминания, PWA и Web Push.
- REST API со Swagger и сохранение данных в PostgreSQL.

## Практика QA

Стенд подходит для ручного и API-тестирования, проверки мобильного интерфейса и PWA, работы с DevTools, Charles/Fiddler, Postman и SQL. Можно клонировать репозиторий для практики Git и развернуть собственное окружение.

Для проверки переводов удобно создать несколько вымышленных аккаунтов и открыть их в разных профилях браузера. Так можно сравнить результат со стороны отправителя и получателя, данные API и записи в базе.

## Локальная установка

Нужны Git и запущенный Docker Engine или Docker Desktop с поддержкой Compose.

```sh
git clone https://github.com/egorcodd/cardo-qa.git
cd cardo-qa
docker compose up -d --build
```

Первый запуск скачивает зависимости и собирает сервисы. После запуска доступны:

| Что открыть | Адрес |
| --- | --- |
| Приложение | http://localhost:8942 |
| Swagger | http://localhost:8942/api/docs |
| Спецификация OpenAPI | http://localhost:8942/api/openapi.json |
| PostgreSQL | localhost:5434, база `cardo` |

Настройки перечислены в `.env.example`. Для изменения локальных портов создай рядом файл `.env`. Данные хранятся в Docker volume и сохраняются после обычной остановки.

```sh
docker compose down
```

Чтобы продолжить практику, снова выполни `docker compose up -d`. Состояния контейнеров доступны через `docker compose ps -a`, логи отдельного сервиса, например, через `docker compose logs banking`.

## Архитектура

В микросервисной архитектуре Cardo пять приложений. Каждое запускается в своём Docker-контейнере:

| Сервис | Назначение |
| --- | --- |
| `gateway` | Интерфейс, публичный API и проверка сессии |
| `customer` | Регистрация, профили и сессии |
| `banking` | Счета, карты, переводы и история операций |
| `engagement` | Награды, уведомления и доставка push |
| `rates` | Курсы валют |
| `postgres` | Хранение данных сервисов |

Сервисы общаются через HTTP и события через outbox/inbox. PostgreSQL один, с отдельными схемами и ролями customer, banking, engagement и rates. `db-setup` подготавливает локальные схемы и роли; его завершение с кодом 0 нормально.

Исходники интерфейса находятся в `apps/web`, сервисов в `services`, общие контракты в `packages/contracts`, технические функции в `packages/shared`.

## API и документация

Swagger доступен на `/api/docs`; спецификация на `/api/openapi.json`. Для запросов в Postman используй Bearer Token из ответа регистрации или входа. В браузере авторизация работает через cookie.

Правила переводов, комиссии, устройство сервисов и примеры работы описаны в [документации проекта](docs/PROJECT.md). Правила обращения с данными описаны в [SECURITY.md](SECURITY.md).

# Данные и конфигурация учебного стенда

Cardo — открытый учебный стенд с намеренными функциональными ошибками. Используйте вымышленные имена, телефоны, учебные балансы и карты. Не загружайте настоящие банковские реквизиты, документы и персональные данные учеников в репозиторий или демонстрационные фикстуры.

## Что можно публиковать

Исходники, миграции схем, искусственные фикстуры, тесты и `.env.example`. Пароли с суффиксом `_dev` и `cardo-local-internal` предназначены для локальной практики и не должны давать доступ к внешней инфраструктуре. Вымышленные демонстрационные аккаунты могут иметь общий учебный пароль; он не даёт административного доступа. Не используй его для личного аккаунта.

## Что хранится отдельно

- Серверный `.env` и `docker-compose.override.yml` с реальными паролями сервисов.
- SSH-ключи, токены, приватные VAPID-ключи и конфигурации с ними.
- Дампы, резервные копии, загруженные файлы, журналы и реальные пользовательские данные.
- Приватный каталог преподавателя и ответы из `.local`.

Эти файлы исключены из Git и Docker context. Исключения не удаляют файл из прежнего коммита, поэтому перед публикацией нужно проверять текущие файлы и историю Git сканером секретов. Обнаруженный действующий секрет сначала отзывают или меняют, затем согласуют очистку истории; удаления только в новом коммите недостаточно.

## Внешнее размещение

Не используйте локальные пароли инфраструктуры для публичного сервера. PostgreSQL и внутренние HTTP-порты должны оставаться недоступными извне. HTTPS, реальные ключи и резервные копии настраиваются вне репозитория. Отсутствие индексации и обфускация JS не заменяют ограничения доступа и проверку прав.

О баге, который раскрывает действующий секрет или реальные персональные данные, сообщайте владельцу напрямую, не публикуя сами данные в issue. Учебные ошибки в сценариях оформляйте как обычные баг-репорты.

## Инструменты практики

В расширенном окружении ученик читает отдельные темы Kafka с разрешёнными полями и индексы cardo-logs-*. Рабочая тема с данными для создания уведомлений доступна сервисам. Права проверяются на брокере и в Elasticsearch, помимо ограничений интерфейсов.

Grafana использует роль Viewer и источник Elasticsearch с отдельной ролью чтения. В Kibana ученик имеет Read для Discover и Dashboards только в разделе Cardo. Управление темами, отправка сообщений, смена offsets, изменение журналов и администрирование пользователей не входят в учебный доступ.

Пароли сервисов и ключи шифрования для внешнего окружения создаются отдельно. Скрипт scripts/prepare-observability-env.mjs сохраняет их в исключённый из Git файл .local/observability.env и отказывается заменять существующие реквизиты. В E-QA передаётся только пароль общего аккаунта чтения; его отображение находится на защищённой странице проекта. Брокер, Elasticsearch и сборщик не получают публичных портов.
